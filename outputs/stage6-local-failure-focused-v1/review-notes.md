# 6단계 사람 검토 노트

이 문서는 실패 사례 기반 검색 조건 비교를 나중에 사람이 재검토하기 위한 기록이다. 원시 결과는 `retrieval_results.jsonl`, 표 형식 결과는 `retrieval_results.csv`, 자동 집계는 `retrieval_summary.json`에 있다.

## 한 문장 요약

Q2와 Q3가 baseline의 실패 사례를 보완했고, Q3의 정렬 지표가 가장 높았다. MMR은 현재 조건에서 크게 악화됐고 C2는 차이가 없었다.

## 결과 해석

- Q2는 기능명을 원문에 추가해 `DEV-REBUILD-001`을 회수했고 Recall 1.0을 달성했다.
- Q3는 기능·입력·권한·상태를 구조화해 Q2와 같은 Recall을 유지하면서 nDCG를 높였다.
- MMR λ=0.7은 결과 다양성은 의도했지만, 관련 TC와의 유사성보다 분산을 우선해 많은 관련 근거를 제외했다.
- C2는 현재 2,000자 기준에서 baseline과 최종 순위가 같아 청킹의 실질 효과를 확인하지 못했다.

## 사람이 확인할 질문

- [ ] Q3가 회수한 추가 TC가 실제로 `DEV-REBUILD-001`의 숨은 조건을 충분히 설명하는가?
- [ ] Q3 구조화 필드가 사용자 요청에서 직접 제공된 정보인가, 평가자가 정답을 보고 추가한 정보인가?
- [ ] MMR이 제외한 TC 중 중복이 아니라 상호 보완적인 근거가 있었는가?
- [ ] 2,000자보다 긴 실제 TC를 추가해 C2를 다시 평가해야 하는가?
- [ ] 기능 대/중분류 필터를 안전하게 적용할 수 있는 사례 필드를 먼저 보강해야 하는가?
- [ ] 제품 용어 사전을 사람 검토 후 terms 전처리 실험에 사용할 것인가?

## 확정하면 안 되는 주장

- Q3가 모든 데이터와 모델에서 최적이다.
- MMR은 일반적으로 검색에 해롭다.
- C2 청킹은 효과가 없다.
- Q3의 Recall 1.0이 전체 요구사항 커버리지를 뜻한다.
- 구조화 질의가 항상 사용자 입력만으로 생성 가능하다.
