# Stage 7 Vector DB 재검증 완료

## 검증 목적

기존 메모리 벡터 검색이 아니라 SQLite `vector_index`에 저장된 E2 벡터를 읽어 검색하는 경로를 검증했다. 기존 운영 인덱스와 이전 Stage 7 인덱스는 변경하지 않았다.

## 전체 인덱스

- `stage7-full-local-hash-e2-v1`: Local Hash, 384차원, 2,571건
- `stage7-full-bge-m3-e2-v1`: BAAI/bge-m3, 1,024차원, 2,571건

두 인덱스 모두 E2/C1 기준이며 모델별 벡터를 혼용하지 않는다.

## 재검증 결과

| 조건 | 저장 벡터 | P@10 | R@10 | MRR@10 | nDCG@10 | 평균 검색 초 |
|---|---|---:|---:|---:|---:|---:|
| M0 BM25 | 사용 안 함 | 0.2667 | 0.9778 | 0.9667 | 0.9147 | 0.0052 |
| M1 Local Hash Vector | SQLite | 0.2733 | 0.9889 | 0.9333 | 0.8460 | 0.0108 |
| M2 BGE-M3 Vector | SQLite | 0.2800 | 1.0000 | 1.0000 | 0.9848 | 0.1924 |
| M3 Local Hash Hybrid RRF | SQLite + BM25 | 0.2800 | 1.0000 | 0.9667 | 0.9227 | 0.0183 |
| M4 BGE-M3 Hybrid RRF | SQLite + BM25 | 0.2800 | 1.0000 | 0.9667 | 0.9501 | 0.1045 |

M1~M4는 질의만 임베딩하고 문서 벡터는 SQLite에서 읽었다. M2/M4도 모델 다운로드 후 실제 BGE-M3로 실행했다.

## 해석

저장된 Vector DB를 사용하는 경로에서도 BGE-M3 Vector가 개발 평가셋의 MRR/nDCG에서 가장 높았다. 다만 라벨이 있는 15개 사례 기준이며, 전체 TC 요구사항 커버리지를 증명하지 않는다. 최종 평가셋 검증과 생성 품질 비교는 별도 작업이다.
