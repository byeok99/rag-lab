# 1단계 사람 검토 노트

이 문서는 baseline 파이프라인과 평가 데이터 검증 결과를 나중에 사람이 재검토하기 위한 해석 기록이다. 원시 결과는 `retrieval_results.jsonl`, 표 형식 결과는 `retrieval_results.csv`, 자동 집계는 `retrieval_summary.json`에 있다.

## 한 문장 요약

1단계는 검색 성능을 확정한 실험이 아니라 **평가 데이터, 실행 기록, 지표 계산, 분할 및 누출 방지가 정상 동작하는지 확인한 단계**다.

## 결과 해석

- 개발 사례 16건이 사람 검토 완료 상태이며 최종 조건 재발견 사례 4건은 미검토 상태로 분리돼 있다.
- 관련성 라벨 15건의 baseline Recall@5는 0.3756으로 낮았다. 현재 E4 local-hash baseline이 관련 TC를 많이 놓친다는 신호다.
- Precision@5 0.1733은 상위 5개 중 라벨상 관련 TC가 평균적으로 적었다는 뜻이다. 다만 관련성 라벨이 전수 판정은 아니어서 미판정 TC를 모두 무관하다고 단정할 수 없다.
- 무근거 요청 1건을 지표 평균에서 제외한 것은 관련 정답이 없는 사례를 일반 Recall 계산에 섞지 않기 위한 처리다.
- 이 단계의 핵심 성과는 지표 자체보다 오류 0건, 중복 반환 0건, 숨긴 TC 유출 0건과 실행 상태 분리 검증이다.

## 다음 단계로 넘긴 판단

- baseline E4가 낮은 이유가 임베딩 입력 구성 때문인지 확인하기 위해 E1~E4 비교가 필요했다.
- Top-K나 검색 방식을 동시에 바꾸지 않고 먼저 임베딩 입력만 비교하기로 했다.
- 실제 의미 임베딩/API 실험은 이후 사용자 결정으로 제외됐으므로, 1단계의 “실제 임베딩 후속 검증”은 현재 범위에 포함되지 않는다.

## 사람이 확인할 질문

- [ ] 개발 사례 16건의 관련 TC 라벨이 충분하고 누락이 없는가?
- [ ] 최종 조건 재발견 사례 4건은 최종 사용 전에 별도 검토할 것인가?
- [ ] 무근거 요청 1건이 실제 무근거 사례로 적절한가?
- [ ] Recall이 낮은 사례의 정답 TC가 검색 인덱스에 실제 포함됐는가?
- [ ] 개발/최종 분할 사이에 의미적으로 유사한 TC가 추가로 섞이지 않았는가?

## 확정하면 안 되는 주장

- baseline 검색 품질이 제품 사용에 충분하다.
- 전체 요구사항 커버리지를 측정했다.
- 실제 제품 동작 정확성을 검증했다.
- local-hash 결과가 실제 의미 임베딩 성능을 대표한다.
