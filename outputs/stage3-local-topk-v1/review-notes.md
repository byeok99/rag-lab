# 3단계 사람 검토 노트

이 문서는 Top-K 비교 결과를 나중에 사람이 재검토하기 위한 해석 기록이다. 원시 결과는 `retrieval_results.jsonl`, 표 형식 결과는 `retrieval_results.csv`, 자동 집계는 `retrieval_summary.json`에 있다.

## 한 문장 요약

K를 늘릴수록 관련 TC를 덜 놓쳤지만 불필요하거나 미판정인 TC도 늘었다. **현재 단계에서는 관련 근거 누락을 우선해 K=10을 선택하고 K=5를 효율 대안으로 남겼다.**

## K별 해석

- K=3은 Precision 0.5778로 가장 깔끔하지만 Recall 0.7089이며, 15개 중 1개 사례에는 관련 근거가 하나도 포함되지 않았다.
- K=5는 Recall 0.8189이고 모든 라벨 사례에 관련 근거가 최소 하나 포함됐다. 평균 선택 컨텍스트는 약 550토큰이었다.
- K=10은 Recall 0.9267, nDCG 0.7850으로 상승했고 평균 선택 컨텍스트는 약 1,125토큰이었다.
- K=15는 Recall 0.9600으로 가장 높지만 K=10 대비 개선은 0.0333이고, 전달 TC는 50% 늘며 Precision은 0.1733까지 낮아졌다.
- MRR은 K=5부터 같으므로 K를 늘려도 첫 관련 TC의 위치는 개선되지 않았다.

## 왜 K=10을 선택했는가

- K=5보다 관련 TC 회수율이 0.1078 높았다.
- 모든 라벨 사례에 관련 TC가 포함됐고 4,000토큰 예산 절단도 없었다.
- K=15의 추가 Recall 이득보다 컨텍스트 증가와 잡음 위험이 더 크다고 판단했다.
- Precision과 컨텍스트 크기를 더 중요하게 보면 K=5도 타당한 선택이다.

## 사람이 확인할 질문

- [ ] K=10에서 추가된 미판정 TC가 실제로 무관한가, 라벨이 빠진 것인가?
- [ ] K=5에서 놓치고 K=10에서 찾은 관련 TC가 생성에 반드시 필요한 근거인가?
- [ ] K=15가 추가로 찾은 관련 TC의 가치가 컨텍스트 증가를 정당화하는가?
- [ ] 약 1,125토큰의 검색 근거가 실제 Codex 생성 품질과 비용에 적절한가?
- [ ] 관련 근거 없음 사례에서 항상 K개를 반환하는 동작을 별도 임계값으로 보완해야 하는가?

## 확정하면 안 되는 주장

- K=10이 모든 프로젝트와 검색 모델에서 최적이다.
- Precision 하락분이 모두 실제 무관 TC다.
- 높은 Recall이 자동으로 높은 생성 품질을 만든다.
- 현재 결과로 근거 부족 요청을 판정할 수 있다.
